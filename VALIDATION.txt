0.3.3 QUIET RELEASE POLICY — SUPERSEDES EARLIER FULL-SPEED FALLBACK
- User explicitly rejected leaving fans at 100% just because a test/session ended
  or a generic safety fallback was invoked. The original TT controller was
  restarted with its unchanged quiet curves immediately.
- Each fan's running duty is captured before the first speed write. Normal close
  restores that duty, not 100%. RGB-only and monitor-only sessions do not write
  speed on close. Missing baseline prevents takeover entirely.
- Missing/stale temperature releases control instead of inventing an emergency
  full-speed demand. Initial missing readings prevent opening the controller.
- Real measured critical temperature (85 C) remains a separate emergency case;
  user-selected Full mode and actual high-temperature curves can still reach 100%.
- No fixed restored duty is represented as a firmware curve or guaranteed safety.
  Keep the proven vendor setup active until the revised release is validated.
- Added fake-HID tests for exact stop restoration, RGB-only close, unavailable
  baseline and the separate genuine critical-temperature case.
- Subsequent user instruction: no more live hardware experiments tonight. The
  original TT Silent settings are left untouched; new work is source/mock-only.
- Valid UI curve/RGB/widget changes now save/apply automatically after a 450 ms
  debounce. Device/wiring changes remain pending until explicitly stopped/rearmed.
  Silent/Custom/Full quick buttons affect managed fans only. Custom restores the
  retained original custom curve instead of replacing it with Silent permanently.
